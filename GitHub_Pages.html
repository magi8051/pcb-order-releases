시작 전에 꼭 확인하세요. GitHub Pages 사이트는 주소를 아는 사람이면 누구나 볼 수 있어요. 무료 계정에서는 저장소도 Public(공개)이어야 해요. 발주 내역처럼 회사 내부 자료는 공개해도 되는지 먼저 확인하세요.

0. 전체 흐름 한눈에 보기

①~③은 처음 한 번만, 이후 수정은 ②만 반복하면 돼요.

1. 저장소(Repository) 만들기

  1. github.com에 로그인해요.
  2. 오른쪽 위 + ▾를 누르고 New repository를 눌러요. (바로가기: github.com/new)
  3. Repository name에 저장소 이름을 영어로 입력해요. 예: pages-test, jlcpcb
    이름 아래에 초록색으로 "… is available."가 뜨면 사용할 수 있는 이름이에요.
  4. Description(설명)은 선택이에요. 비워 둬도 돼요.
  5. Choose visibility가 Public인지 확인해요.
  6. README, .gitignore, license는 그대로 두고, 오른쪽 아래 Create repository를 눌러요.
빨간 테두리 순서대로: ① + 메뉴 → ② 이름 입력 → ③ Public 확인 → ④ Create repository

2. index.html 올리기

파일 이름은 반드시 index.html(소문자)이어야 주소만으로 페이지가 열려요. 다른 이름이면 주소 뒤에 파일 이름까지 붙여야 해요.

방법 A. 이미 만든 HTML 파일 끌어다 놓기 (추천)

  1. 내 PC에서 올릴 HTML 파일 이름을 index.html로 바꿔요.
  2. 저장소 화면에서 Add file ▾ → Upload files를 눌러요.
    빈 저장소라면 화면 가운데의 uploading an existing file 링크를 눌러요.
  3. index.html을 점선 영역에 끌어다 놓아요.
  4. 아래쪽 Commit changes를 눌러요.

방법 B. 웹 편집기에 직접 붙여넣기 (테스트 때 쓴 방법)

  1. 저장소 화면에서 Add file ▾ → Create new file을 눌러요. 빈 저장소라면 creating a new file 링크를 눌러요.
  2. 위쪽 파일 이름 칸에 index.html을 입력해요.
  3. 아래 큰 편집 칸에 HTML 내용을 붙여넣어요.
  4. 오른쪽 위 Commit changes...를 누르면 창이 떠요. 메시지는 그대로 두고 창 안의 Commit changes를 한 번 더 눌러요.
① 파일 이름 index.html → ② 내용 붙여넣기 → ③ Commit changes... 누르고, 뜨는 창에서 Commit changes 한 번 더

3. GitHub Pages 켜기

  1. 저장소 위쪽 탭에서 Settings(⚙)를 눌러요. 화면이 좁으면 More ▾ 안에 있어요.
  2. 왼쪽 메뉴 아래쪽의 Pages를 눌러요.
  3. Source가 Deploy from a branch인지 확인해요.
  4. Branch에서 None ▾을 눌러 main을 고르면 옆에 / (root)가 나타나요. 그대로 둬요.
  5. Save를 눌러요. 위쪽에 "GitHub Pages source saved."가 뜨면 성공이에요.
① Settings → ② Pages → ③ Branch를 main으로 → ④ Save

4. 배포 확인하고 접속하기

  1. 저장소 위쪽 Actions 탭을 눌러요. pages build and deployment 작업이 보여요.
  2. 노란 원(진행 중)이 초록 체크(완료)로 바뀔 때까지 기다려요. 보통 1분 안팎이 걸려요.
  3. 브라우저에서 https://내아이디.github.io/저장소이름/로 접속해요. 아이디는 소문자로 바뀌어요.
    예: https://developerminki.github.io/pages-test/
  4. Settings → Pages 화면 위쪽에도 "Your site is live at …"로 주소가 표시돼요.

5. 내용 수정하기

한 번 설정한 뒤에는 파일만 바꾸면 같은 주소에 자동으로 반영돼요. Pages 설정은 다시 하지 않아도 돼요.

방법순서
파일 통째로 교체Add file ▾ → Upload files → 새 index.html을 끌어다 놓기 → Commit changes. 같은 이름이면 덮어써요.
웹에서 직접 고치기저장소에서 index.html 클릭 → 오른쪽 위 연필(✎) 아이콘 → 수정 → Commit changes... → Commit changes

커밋하면 Actions에서 배포가 다시 돌고, 1~2분 뒤 반영돼요. 바로 안 바뀌면 Ctrl + F5로 강력 새로고침해요.

안 될 때 확인할 것

증상확인할 것
404 "There isn't a GitHub Pages site here"Actions 탭에서 배포가 끝났는지 확인해요. 끝났는데도 안 되면 Settings → Pages에서 Branch가 main으로 저장됐는지 봐요.
404인데 배포는 완료됨파일 이름이 정확히 index.html(소문자)인지, 폴더 안이 아니라 저장소 맨 위에 있는지 확인해요.
Pages 메뉴에 Branch 선택이 없음저장소가 Private이면 무료 계정에서는 Pages를 쓸 수 없어요. Settings → General 맨 아래에서 Public으로 바꿔요.
수정했는데 예전 화면이 보임배포가 끝났는지 확인하고 Ctrl + F5로 새로고침해요.
한글이 깨짐HTML의 <head> 안에 <meta charset="utf-8">가 있는지 확인해요.

테스트 저장소 지우기

저장소 Settings → General 맨 아래 Danger Zone → Delete this repository를 눌러요. 저장소 이름을 입력하라고 하면 입력해서 확인해요. 지우면 사이트도 함께 사라지고 되돌릴 수 없어요.

(선택) 명령어로 올리는 방법

PC 폴더에서 계속 작업하면서 자주 올릴 거라면 Git 명령어가 편해요. 1단계(저장소 만들기)와 3단계(Pages 켜기)는 웹에서 똑같이 하고, 2단계만 아래 명령어로 바꾸면 돼요.

처음 한 번 (PowerShell에서 HTML이 있는 폴더로 이동한 뒤 실행)

git init -b main
git add index.html
git commit -m "첫 업로드"
git remote add origin https://github.com/내아이디/저장소이름.git
git push -u origin main

처음 push할 때 GitHub 로그인 창이 뜨면 로그인해요.

수정할 때마다

git add index.html
git commit -m "내용 업데이트"
git push
폴더에 엑셀, memos.json, _tool/처럼 올리면 안 되는 파일이 있다면 .gitignore 파일에 이름을 적어 두세요. 그리고 git add . 대신 git add index.html처럼 올릴 파일만 지정하면 실수로 올라가는 일을 막을 수 있어요.
